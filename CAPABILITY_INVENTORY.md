# Capability Inventory

Registry of which profile has which flags, modules, and strategies. The
point of this file is to **prevent duplicate builds**: before adding any
new feature, check here whether another profile already has it.

Active profile: `config/diocese.php` → `config/profiles/{DIOCESE_PROFILE}.php`
(`DIOCESE_PROFILE` env, default `wis`).

Legend: ✅ enabled · ❌ disabled/absent · (key) where the value lives

---

## Capability flags (`capabilities.*`)

| Flag | `wis` | `mcgh` | Drives |
|---|---|---|---|
| `attendance.default_mode` | `register` | `headcount` | New-session default; WIS = per-member roster, MCC = Men/Women/Children door tally |
| `cells.enabled` | ✅ | ❌ | Sidebar + router show/hide `/cells/*` |
| `modules.confirmations` | ❌ | ❌ | Registers the Confirmations module (table + routes + UI). Default OFF everywhere — flip per profile to activate |

Rule: capabilities drive **UI and soft defaults only**. Authorization always
stays with Spatie permissions.

## Adding a new flag / module / strategy

1. Read this file first — the feature may already exist behind another flag.
2. **Flag**: add under `capabilities.*` in both profiles; gate Sidebar/route
   with `capability(...)` and (if scoped) the backend.
3. **Module**: copy `app/Diocese/Modules/Confirmations/` structure; register
   the provider hook is already generic (`registerModules()` in
   `DioceseServiceProvider`). Frontend page is bundled always but only
   mounted behind `CapabilityGate`.
4. **Strategy**: implement the contract, add a `match` arm in
   `DioceseServiceProvider::register()`.
5. Update this file so the next builder knows it exists.
